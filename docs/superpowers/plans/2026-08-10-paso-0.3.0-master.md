# Paso 0.3.0 Master Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Hello! My Paso! 0.3.0 with user-confirmed local-AI journal drafting, a cohesive GPT-image-backed visual refresh, and verified Android release artifacts.

**Architecture:** Three independently reviewable workstreams cover the AI boundary, visual system, and integrated release. Local AI is a non-persistent adapter around an owner-controlled OpenAI-compatible runtime; visual work changes presentation and truthful map copy; release work versions, documents, verifies, signs, and publishes the integrated app.

**Tech Stack:** Next.js 16 static export, React 19, TypeScript 5, Vitest, Tailwind CSS 4, Capacitor 8, Android Gradle, OpenAI-compatible local inference, GPT Image.

## Global Constraints

- Core journaling, maps, photos, SQLite, backup, and XP work with AI disabled.
- AI output is an editable in-memory draft and cannot directly invoke persistence.
- No cloud AI endpoint, bundled model weight, API key, background inference, photo-library scan, or automatic save.
- Every generation requires a visible payload preview and excludes coordinates, EXIF, persistent IDs, backup data, and unrelated records.
- Loopback is allowed by default; literal private-LAN IPs require explicit ownership confirmation; public endpoints and redirects are rejected.
- Generated art contains no people, landmark, logo, text, map, or simulated user photo.
- Static export and Capacitor remain intact; no API route, Server Action, or hosted backend is introduced.
- Target version is `0.3.0` with Android `versionCode 6` unless Play Console proves a higher code is required.
