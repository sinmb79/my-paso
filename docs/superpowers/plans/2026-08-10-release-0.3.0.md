# Paso 0.3.0 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Produce, verify, document, sign, publish, and archive the Hello! My Paso! 0.3.0 Android update.

**Architecture:** Release work begins only after AI and visual workstreams pass focused tests. The pipeline fixes the existing lint scope, synchronizes version/privacy/store documentation, builds web/mobile/Android artifacts, validates signatures and hashes, then uses the existing Google Play closed-testing path and GitHub remote.

**Tech Stack:** npm, Next.js, Capacitor, Gradle, Android build tools, PowerShell, Git, GitHub CLI, Google Play Console.

## Global Constraints

- Do not reveal signing passwords, keystore content, cookies, service-account data, or browser session tokens.
- Release signing uses the existing user-owned properties file outside the repository.
- Play Console version code must be unused; use 6 only after confirming the existing v5 state.
- The 0.2.0 "no off-device collection" declaration cannot be reused when private-LAN AI is enabled.
- Generated art cannot replace real app screenshots.
- Do not tag, push a release, or upload an AAB until all local verification gates pass.
- If Play Console requires new legal answers or an interactive account challenge, preserve the verified artifact and record the exact required user action without weakening declarations.

- [ ] **Step 2: Add a purpose-built native plugin**

Register an Android-only Capacitor plugin that accepts only POST requests to the fixed `/v1/chat/completions` path on exact HTTP loopback origins. Provide a loopback-only, bounded OpenAI-compatible fixture for dummy-data emulator testing. It must expose no LAN listener, persist no content, log only request metadata, return a schema-valid Korean draft, and stop cleanly.
